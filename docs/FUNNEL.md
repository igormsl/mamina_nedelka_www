# Статья → Telegram → первый результат

Сверка локального кода продукта: 15.10.2026 MSK. Runtime и пользовательский Telegram-сеанс отдельно не подтверждены. Repo бота использован только на чтение; его незакоммиченные изменения сохранены.

## Реализованный путь на сайте

Статья отвечает на вопрос → в конце предлагает посмотреть свою неделю → ссылка открывает `mamina_nedelka_bot` → пользователь нажимает «Старт» → бот показывает вход в Mini App → согласия и профиль/срок → материалы текущей недели. Первый полезный результат: прочитать свою неделю и записать вопрос для приёма. Это путь, найденный в текущем локальном коде, а не запись пройденного production-сеанса.

На главной показаны эти шаги. В статьях одна завершающая вставка и обычная кнопка навигации. Нет таймеров, навязчивых всплывающих окон и обещания медицинской оценки. Бот не должен быть следующим действием при срочном симптоме.

Сверены `app/handlers.py` (`/start`, shell door, first-touch), `app/templates.py`, `app/plan_access.py`, `app/plan_pricing.py`, `BOT_SPEC.md`, экраны Mini App. Тарифы сайта описаны качественно: бесплатный доступ, напоминания Basic+, анализы/партнёр Premium. Числовые цены и дневные лимиты не обещаются: они имеют runtime overrides. Питание как рабочая функция не рекламируется. AI обозначен как источник возможных ошибок.

## Метки ссылок

| Пример | Значение |
|---|---|
| `landing_hero` | Главная, основная кнопка |
| `landing_nav` | Главная, навигация |
| `landing_footer` | Главная, завершающий блок |
| `blog_nav` | Каталог, навигация |
| `blog_a0047_nav` | Статья A-0047, навигация |
| `blog_a0047_article_end` | Статья A-0047, конец текста |
| `blog_a0047_article_end_tg` | То же, вход с `utm_source=telegram` |

Allowlist каналов: `telegram→tg`, `threads→th`, `instagram→ig`, `yandex→ya`, `google→go`. Наличие метки не означает разрешение рекламы на платформе: см. [LEGAL.md](LEGAL.md). Пример размеченной ссылки для допустимого информационного размещения: `https://maminanedelka.ru/blog/polozhitelnyy-test.html?utm_source=telegram`.

Метка содержит ID статьи, а не симптомы, срок, запрос поиска или контакт. UTM передаётся между страницами главной/блога только через URL; cookie/storage не используются. Метка связана с профилем после запуска бота, поэтому её нельзя называть анонимной статистикой. URL страницы тоже может косвенно раскрывать интерес к медицинской теме; его не следует дополнительно связывать с рекламными идентификаторами.

## Что действительно измеряется

- Сайт формирует правильную ссылку. На нажатии создаётся локальное DOM-событие `mamina:bot-click` с `event`, `page`, `placement`, `source`. Оно **никуда не отправляется, не хранится**, счётчика кликов пока нет.
- Локальный код бота принимает произвольную короткую start-метку допустимого формата и сохраняет её через `set_signup_source_if_empty`. Это **первый источник**, не журнал всех запусков и не ретаргетинг. Для уже заполненного источника повторный переход не перепишет атрибуцию. Наличие реализации не подтверждает её версию на production.
- Экспорт источников в продукте позволяет строить агрегаты после сверки live-версии и правового основания. Никакая статистика, конверсия или результат кампании в этой задаче не выдуманы.

## Предлагаемое измерение после правовой проверки

1. `bot_click`: общий счётчик по дню/странице/месту/каналу; без текста поиска, полного referrer, срока и идентификаторов посетителя. Возможный сборщик на своём домене в РФ либо выбранная аналитика — отдельная реализация после уточнения обработки, согласий и журналов.
2. `signup_source`: число новых профилей с данной первой меткой. Для числа *всех* стартов нужен отдельный event в боте; сейчас его наличие не предполагается.
3. `onboarding_completed`, затем `first_week_view`: серверные события продукта, одно на пользователя; нужны отдельная задача в repo бота, согласованная минимизация и срок хранения. Их пока не добавляли.
4. Для одного периода и одной когорты считать `новые профили / клики`, `завершили профиль / новые профили`, `увидели неделю / завершили профиль`. Это разные знаменатели. Данные Search Console/Webmaster о показах и поисковых переходах дополняют воронку без JS-счётчика на сайте.

Не подключать Метрику/Webvisor автоматически ради «полноты»: на страницах здоровья это отдельный вопрос данных. До реализации кликов нельзя публиковать CTR сайта или приписывать все регистрации прочтению статьи.

## Приёмочный сценарий в Telegram

На тестовом новом профиле: открыть A-0047 → нажать нижнюю кнопку → проверить метку → Start → Mini App → прочитать документы и дать необходимые согласия → заполнить допустимые тестовые данные → открыть неделю → сохранить один вопрос. Зафиксировать экран первого результата и подтверждённый первый источник без вывода персональных данных в отчёт. Отдельно проверить существующий профиль: повторный переход не сбрасывает источник/данные. Проверить отказ от согласия, возврат и отсутствие обязательной оплаты до бесплатного результата.

В текущей задаче проверены DOM, ссылки, ограничения меток и кодовый путь. Вход в реальный Telegram и оплата не выполнялись; HTTP 200 `/health` не заменяет этот сценарий.
